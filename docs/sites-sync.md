# Sites 코드의 GitHub 보관

실제 서비스, 환경변수와 D1 데이터는 현재 Sites에서 계속 운영합니다. GitHub는 소스 코드 보관용입니다.

## 현재 방식

Sites 수정 후 사용자가 해당 저장소로 푸시해 달라고 요청하면, 최신 코드를 `main`에 직접 반영합니다. 수정할 때마다 자동으로 GitHub에 저장하지는 않습니다.

기존 `Sync Sites source` Actions 워크플로는 `main`과 `sites-sync` 양쪽에서 제거했습니다. `sites-sync` 브랜치와 기존 실행 이력, `.sites-sync/state.json`은 과거 동기화 기록이며 현재 소스의 최신 상태를 나타내는 지표로 사용하지 않습니다.

## 요청된 푸시 절차

1. 사용자가 저장을 요청한 Sites 소스 커밋과 현재 GitHub `main`을 확인합니다.
2. 비밀번호, 세션 키, 환경변수 파일, 실제 DB 데이터와 백업, 인증 토큰이 포함되지 않도록 검토합니다. 기존 `.github/scripts/sites_sync.py`의 export 명령은 추적된 앱 소스만 내보내는 보조 도구로 사용할 수 있습니다.
3. 앱 소스의 추가·수정·삭제를 `main`에 직접 반영합니다. GitHub 문서와 사용자 추가 파일을 보존하고 강제 push하지 않습니다.
4. 반영된 커밋과 파일을 확인하고 결과를 보고합니다.

GitHub 코드 저장은 Sites 재배포나 DB 변경을 수행하지 않습니다. 가족 비밀번호와 실제 운행·정비 기록은 계속 Sites와 D1에만 보관합니다.
